# Реестр инвазивной пренатальной диагностики

Веб-сервис для отделения пренатальной диагностики. Заменяет бумажный журнал и Excel-таблицу:
одна запись ведётся от направления до исхода беременности — показание, протокол процедуры,
образец, метод исследования, результат лаборатории, чем закончилась беременность. Ничего не
теряется: всегда видно, где сейчас каждый образец, по кому не внесён результат и по кому не
внесён исход.

Работают одновременно врачи, лаборатория и администратор — у каждого свой набор прав. Все
изменения подписаны автором и временем, удаления нет: запись можно только аннулировать с
указанием причины. Отчёты (объёмы, структура показаний, диагностический выход, частота
осложнений) считаются на лету и выгружаются в Excel.

Подробное описание того, что сервис должен уметь, — в [docs/SPEC.md](docs/SPEC.md).
Как поставить его на свой сервер — в [docs/DEPLOY.md](docs/DEPLOY.md), как выложить
демонстрационную версию на Vercel — в [docs/DEPLOY-VERCEL.md](docs/DEPLOY-VERCEL.md).

## Что уже готово

По плану из раздела 10 спецификации сделаны первые три этапа:

- **Этап 1 — ядро.** Вход и роли, пациентки, беременности и плоды (в том числе двойни),
  скрининг, пошаговый мастер новой процедуры, журнал процедур, справочники, выгрузка в Excel.
- **Этап 2 — лаборатория.** Очередь образцов, статусы, дедлайны по методам, ввод результатов.
- **Этап 3 — замыкание цикла.** Исходы беременности, задачи-напоминания, дашборд «Мой день»,
  отчёты и аналитика.
- **Мобильная версия.** Врачи работают с телефона: выдвижное меню, нижняя панель с основными
  разделами, вместо широких таблиц — карточки. Проверено на ширине 375 px.
- **Заполнение форм по фотографии.** Врач фотографирует бумагу телефоном, сервис распознаёт
  текст и раскладывает его по полям, врач проверяет и сохраняет. Понимает заключения
  цитогенетика, направления, протоколы УЗИ и результаты НИПТ. Распознавание работает
  **целиком на своём сервере** (Tesseract, языковые модели лежат в репозитории) — снимок
  с персональными данными никуда не отправляется.

## Что впереди

- **Этап 4.** Импорт накопленных карт из существующей таблицы Excel (нужен образец файла).
- **Этап 5.** Телеграм-бот: привязка к учётке, уведомления, поиск по коду, фото направлений,
  двухфакторный вход.

## Как запустить у себя на компьютере

Нужен Node.js версии 22 или новее. База при разработке — SQLite, отдельно ставить ничего не надо.

```bash
npm install                 # поставить зависимости
npm run db:push -w server   # создать таблицы в базе
npm run seed -w server      # заполнить справочники и завести учётные записи
npm run dev                 # запустить сервер и веб одной командой
```

После этого:

- веб-интерфейс — **http://localhost:5173**
- API — **http://localhost:3001** (проверка «жив ли»: http://localhost:3001/api/health)

Первые три шага можно выполнить одной командой `npm run setup`.

Чтобы посмотреть систему не на пустой базе, добавьте демонстрационные данные — 12 вымышленных
случаев, покрывающих типичные ситуации отделения: норма, трисомия 21, двойня с разными исходами
у плодов, неудача культивирования, осложнение, незакрытый исход, образцы в работе.

```bash
npm run demo -w server
```

Команда срабатывает только на пустой базе и на рабочей ничего не испортит.

Полезное по мелочи:

| Команда | Что делает |
|---|---|
| `npm run dev` | сервер и веб одновременно, с автоперезапуском |
| `npm run build` | собрать сервер и фронтенд для сервера |
| `npm run db:studio -w server` | открыть базу в браузере (Prisma Studio) |
| `npm run seed -w server` | добавить недостающие справочники, существующие не трогает |
| `npm run demo -w server` | демонстрационные данные (только на пустой базе) |

### Учётные записи по умолчанию

Их создаёт `npm run seed -w server`:

| Логин | Пароль | Роль |
|---|---|---|
| `admin` | `admin123` | администратор |
| `doctor` | `doctor123` | врач (демонстрационный) |
| `lab` | `lab123` | лаборант (демонстрационный) |

> **Это учётки для проверки на своём компьютере, а не для работы.**
> Пароли известны всем, кто читал этот файл. При первом входе система сама потребует
> сменить пароль. Перед тем как пустить в сервис реальные данные пациенток, заведите
> настоящих сотрудников, поменяйте пароль администратора и отключите демонстрационные
> учётки `doctor` и `lab`. Чеклист — в [docs/DEPLOY.md](docs/DEPLOY.md).

## Структура проекта

| Папка | Что внутри |
|---|---|
| `server/` | API: Node 22, Fastify, Prisma. Схема базы — `server/prisma/schema.prisma`, справочники по умолчанию — `server/src/dictionaries.ts` |
| `web/` | Веб-интерфейс: React 19, TypeScript, Vite |
| `docs/` | `SPEC.md` — что сервис должен уметь, `DEPLOY.md` — как развернуть на сервере |

Корневой `package.json` связывает `server` и `web` в один проект (npm workspaces), поэтому
`npm install` в корне ставит зависимости сразу для обоих.

## Как это работает

Главная логика сервиса — жизненный цикл записи. Каждый шаг это и статус в журнале, и фильтр
на дашборде, и повод для напоминания:

```
Черновик
  → Запланирована              дата, врач, кабинет
    → Процедура выполнена      протокол заполнен, образец получен
      → Образец в лаборатории  принят, назначены методы
        → Результат готов      внесён цитогенетиком
          → Результат выдан    врач сообщил пациентке, зафиксирована дата
            → Исход внесён     роды / прерывание / потеря
              → Закрыта
```

Из этой цепочки есть три выхода в сторону:

- **Отменена** — процедура не состоялась;
- **Неудачная попытка забора** — материал получить не удалось;
- **Неинформативный результат** (например, неудача культивирования) — заводится повторная
  процедура со ссылкой на исходную, чтобы в статистике одна пациентка не считалась дважды.

При двойне беременность одна и процедура одна, а плодов несколько: у каждого плода свой
образец, свой результат и свой исход. В журнале это одна процедура и две строки образцов.

## Роли

| Роль | Что видит | Что делает |
|---|---|---|
| **Врач** | все данные пациенток, включая ФИО | Заводит пациентку, беременность, скрининг, заполняет протокол процедуры и передаёт образец, отмечает выдачу результата, вносит исход. Результаты лаборатории видит, но не правит |
| **Лаборант / цитогенетик** | все данные, включая ФИО | Принимает образцы, ведёт их по статусам, назначает методы, вносит и правит результат, кариотип, заключение и файл. Клиническую часть не редактирует |
| **Администратор** | всё | Всё вышеперечисленное плюс пользователи и роли, справочники, настройки, журнал доступа, импорт и экспорт |

Обезличивание внутри системы не требуется — ФИО и данные пациентки доступны всем трём ролям.
Осторожность нужна только на внешнем канале: в телеграм (когда он появится) будут уходить код,
фамилия и статус, а диагноз и текст заключения — только по ссылке в веб-интерфейсе.
