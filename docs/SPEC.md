# Реестр инвазивной пренатальной диагностики — функциональная спецификация

Версия 0.1 (черновик для согласования). Дата: 2026-08-01.

## 1. Что это и для кого

Веб-сервис для отделения пренатальной диагностики. Заменяет бумажный журнал и Excel-таблицу.
Работают одновременно несколько врачей, лаборатория и регистратура.
Телеграм-бот — второй канал доступа (уведомления, быстрый поиск, напоминания), не отдельный продукт.

Задачи, которые сервис закрывает:
1. Единый реестр всех инвазивных процедур (БВХ, амниоцентез, кордоцентез, плацентоцентез).
2. Прослеживаемость: направление → показание → процедура → образец → метод → результат → исход беременности.
3. Ничего не теряется: видно, где сейчас каждый образец и по кому не внесён результат/исход.
4. Отчётность одной кнопкой: объёмы, структура показаний, диагностический выход, частота осложнений.
5. Выгрузка обезличенного массива для анализа и публикаций.

## 2. Роли и права

Три роли — согласовано.

| Роль | Что видит | Что может |
|---|---|---|
| **Врач** | все данные пациенток, включая ФИО | Завести пациентку, беременность, скрининг, протокол процедуры, образец, исход. Видит результаты. Не редактирует чужие результаты лаборатории |
| **Лаборант / цитогенетик** | все данные, включая ФИО | Приём образца, статусы, ввод и правка результата, кариотип, файл заключения. Не редактирует клиническую часть |
| **Администратор** | всё | Всё вышеперечисленное + пользователи, справочники, аналитика, журнал доступа, импорт/экспорт |

Принципы:
- Обезличивание не требуется: ФИО и все данные пациентки доступны всем трём ролям.
- Все изменения подписаны автором и временем, пишутся в журнал.
- Удаления нет — есть «аннулировать с указанием причины». Данные остаются в истории.

## 3. Жизненный цикл записи (главная логика сервиса)

```
Черновик
  → Запланирована (дата, врач, кабинет)
    → Процедура выполнена (протокол заполнен, образец получен)
      → Образец в лаборатории (принят, метод назначен)
        → Результат готов (внесён цитогенетиком)
          → Результат выдан (врач сообщил пациентке, дата выдачи)
            → Исход внесён (роды / прерывание / потеря)
              → Закрыта
```
Отдельные ветки: `Отменена`, `Неудачная попытка забора`, `Неинформативный результат / неудача культивирования` (→ повтор процедуры со ссылкой на исходную).

Каждый статус — это фильтр на дашборде и триггер уведомления в телеграм.

## 4. Экраны

### 4.1 Вход
- Логин + пароль, обязательная смена при первом входе.
- Второй фактор — код в телеграм-бот (или TOTP).
- Автовыход по бездействию (настраивается, по умолчанию 30 мин).
- Никакой саморегистрации: учётки заводит администратор.

### 4.2 Дашборд «Мой день»
Верх — четыре плитки-счётчика, каждая кликабельна и ведёт в отфильтрованный список:
- Процедуры на сегодня / на неделю
- Ожидают результата (с подсветкой просроченных: >21 дня для культуры, >3 дней для QF-PCR)
- Результаты готовы, но не выданы пациентке
- Исход не внесён (срок родов прошёл более 30 дней назад)

Ниже — лента: последние изменения коллег («Иванова внесла результат по PD-2026-047»), и блок «Патологические результаты за неделю» — их не должно потеряться.

### 4.3 Пациентки — список
- Поиск одной строкой: ФИО, код, номер карты, телефон, дата рождения.
- Фильтры: год, врач, показание, вид процедуры, результат, статус, осложнения.
- Таблица: код, ФИО, возраст, срок на момент процедуры, вид процедуры, дата, показание, результат, статус.
- Настраиваемые колонки, сортировка, сохранённые фильтры («мои за 2026», «все патологии»).
- Кнопки: «Новая пациентка», «Экспорт в Excel».

### 4.4 Карточка пациентки
Шапка: код, ФИО, возраст, группа крови и резус, телефон, направившее учреждение. Резус-отрицательная кровь — красная метка (нужен анти-D).

Вкладки:
1. **Паспорт** — паспортные, анамнез (паритет, число беременностей/родов/потерь, ЭКО, отягощённый акушерский и генетический анамнез, наследственные заболевания в семье, кровное родство, приём тератогенов).
2. **Беременности** — у одной женщины может быть несколько беременностей в разные годы. Внутри беременности: срок по последней менструации и по УЗИ, одноплодная/многоплодная.
   **Двойни:** одна беременность → несколько плодов (плод A, плод B), хорионичность и амниональность. У каждого плода свои УЗ-данные, свой образец, свой результат и свой исход. Процедура при этом одна (одна дата, один оператор), но с указанием, из какого плодного мешка получен каждый образец, и числом пункций на плод. Тройни и далее — так же, ограничения на число плодов нет.
3. **Скрининг** — данные, на основании которых направили: срок, КТР, ТВП, носовая кость, венозный проток, PAPP-A и β-ХГЧ (МоМ), расчётный риск по Т21/Т18/Т13, программа расчёта, результат НИПТ, УЗ-находки и пороки.
4. **Процедуры** — список инвазивных вмешательств по этой беременности.
5. **Результаты** — заключения лаборатории.
6. **Исход** — чем закончилась беременность.
7. **Файлы** — сканы направлений, протоколов, бумажных заключений, УЗИ-снимки.
8. **История** — кто, когда и что изменил (аудит).

### 4.5 Мастер «Новая процедура» (пошагово, 4 шага)
Пошаговый — потому что вносить будут между приёмами, и важно не думать, что заполнять.

**Шаг 1. Показание.** Мультивыбор из справочника: возраст ≥35, высокий риск комбинированного скрининга (с указанием числового риска), высокий риск НИПТ, УЗ-маркеры/ВПР, отягощённый анамнез (ХА у предыдущего ребёнка), носительство структурной перестройки у родителя, моногенное заболевание в семье, желание женщины. Плюс поле «риск по программе 1:___».

**Шаг 2. Протокол процедуры.** Дата и время; вид (БВХ / амниоцентез / кордоцентез / плацентоцентез); срок беременности на момент (недели+дни считаются автоматически от даты по УЗИ); доступ (трансабдоминальный / трансцервикальный); калибр иглы; число пункций; объём и качество материала; расположение плаценты; оператор и ассистент; УЗ-аппарат; антибиотикопрофилактика; резус-статус и введение анти-D (доза, дата) — обязательно к заполнению, если резус отрицательный; технические особенности и осложнения непосредственно при процедуре.

**Шаг 3. Образцы.** По одному блоку на каждый плод (при одноплодной — один блок): плод, тип материала (околоплодные воды / ворсины хориона / кровь плода), объём, номер контейнера, кому передан, дата и время передачи, назначенные методы: QF-PCR, кариотипирование культуры, FISH, ХМА (микроматричный анализ), NGS/панель, молекулярный анализ на конкретное заболевание.

**Шаг 4. Проверка и сохранение.** Сводка одним экраном, предупреждения («не указан анти-D при Rh-», «срок для БВХ вне 10–14 недель»), кнопка «Сохранить и распечатать протокол».

Черновик сохраняется автоматически: закрыла вкладку — ничего не потеряла.

### 4.6 Журнал процедур (реестр)
То, что сейчас Excel-таблица. Плоская таблица всех процедур, любые фильтры, экспорт. Здесь же — печать журнала за период.

### 4.7 Лаборатория: очередь образцов
Отдельный экран для цитогенетика — рабочая очередь, а не поиск по пациенткам.
- Колонки: код, ФИО, плод, дата поступления, тип материала, назначенные методы, срок выполнения (дедлайн), статус, ответственный.
- Статусы образца: принят → на культивировании → анализ → результат внесён → выдан. Отдельно: контаминация, неудача культивирования, недостаточный объём.
- Подсветка просрочки.
- Массовые действия: принять партию, назначить метод нескольким.

### 4.8 Ввод результата
Форма под метод (поля меняются в зависимости от выбранного метода):
- Дата готовности, метод, число проанализированных метафаз (для кариотипирования), качество препарата.
- **Категория результата** (выбор из списка — это главное поле для статистики): норма; трисомия 21; трисомия 18; трисомия 13; моносомия X; другая анеуплоидия половых хромосом (47,XXY / 47,XXX / 47,XYY); триплоидия; структурная аберрация (сбалансированная / несбалансированная); мозаицизм; патогенная CNV; CNV неясного значения (VUS); норма по исследованным локусам; неинформативно.
- **Кариотип по ISCN** — свободное поле с валидацией формата и подсказками (`47,XY,+21`).
- Заключение текстом + прикреплённый PDF/скан.
- Кто выполнил, кто проверил (двойной контроль для патологии).
- Если результат патологический — система автоматически ставит задачу «сообщить врачу», шлёт уведомление и требует зафиксировать дату и способ выдачи.

### 4.9 Исход беременности
Открывается по задаче-напоминанию (создаётся автоматически на предполагаемую дату родов). При многоплодной — заполняется по каждому плоду отдельно.
Поля: исход (роды в срок / преждевременные роды / прерывание по медицинским показаниям с указанием срока / самопроизвольный выкидыш / антенатальная гибель / потеряна из-под наблюдения); дата; срок; масса; состояние ребёнка; подтверждение диагноза постнатально (совпал / не совпал — важнейший показатель качества); осложнения, связанные с процедурой (подтекание вод, кровотечение, хориоамнионит, потеря беременности в течение 14 дней после процедуры).

### 4.10 Отчёты и аналитика
Период + фильтры, всё считается на лету:
- Число процедур по видам и по месяцам.
- Структура показаний.
- Структура результатов; **диагностический выход** — доля патологии, в целом и в разрезе показаний (отвечает на вопрос «какое показание реально работает»).
- Частота осложнений и потерь беременности после процедуры (ключевой показатель безопасности, отдельно по операторам).
- Доля неудач культивирования и неинформативных результатов.
- Средний срок выполнения анализа по методам.
- Совпадение пренатального и постнатального диагнозов.
- Нагрузка по врачам.
Каждый отчёт — таблица + график + выгрузка в Excel/PDF.

### 4.11 Импорт из Excel
Загрузка существующей таблицы, сопоставление колонок с полями системы, отчёт об ошибках, предпросмотр, импорт. Одноразовая, но обязательная вещь — накопленное не должно остаться в стороне.

### 4.12 Справочники (заведующий/админ)
Показания, виды процедур, методы, категории результатов, осложнения, исходы, направившие учреждения, операторы, оборудование. Добавление своего значения без программиста. Старые значения архивируются, а не удаляются.

### 4.13 Пользователи, роли, журнал доступа
Список сотрудников, роли, блокировка учётки, сброс пароля, привязка телеграм-аккаунта. Журнал: кто, когда, что открыл и что изменил; фильтр по пациентке и по сотруднику; выгрузка.

### 4.14 Настройки
Реквизиты учреждения, дедлайны по методам (когда результат считается просроченным), правила напоминаний, срок автовыхода.
Печатные формы на этом этапе не делаем — вместо них выгрузка в Excel и печать таблицы из браузера.

### 4.15 Уведомления (в интерфейсе + телеграм)
Событий немного, чтобы не превратилось в шум:
- результат готов; результат патологический (немедленно, врачу и заведующему);
- срок выполнения анализа истекает / истёк;
- напоминание внести исход;
- завтрашние процедуры (утренняя сводка);
- запись изменена другим пользователем.

## 5. Телеграм-бот

Не дублирует веб полностью — закрывает то, что нужно на ходу.

- `/start` — привязка к учётке по одноразовому коду из веб-интерфейса.
- Уведомления из раздела 4.15 с кнопкой «Открыть в системе».
- `/find PD-2026-047` или ввод кода — краткая карточка: статус, метод, срок готовности. Без ФИО и диагнозов в переписке; чувствительное — только по ссылке в веб.
- «Мои процедуры на завтра» — список.
- Фото направления или бумажного заключения → прикрепляется к карточке (бот спрашивает код).
- Двухфакторный код при входе в веб.
- Кнопка «Напомнить позже» на задачах.

По умолчанию в телеграм уходят код, фамилия и статус — без текста заключения и без диагноза; полное содержимое открывается по ссылке в веб-интерфейсе. Уровень детализации настраивается администратором (телеграм — внешний канал, поэтому осторожность здесь оправдана, даже когда обезличивание внутри системы не требуется).

## 6. Работа нескольких врачей одновременно

- Одна запись — один редактор: при открытии на редактирование остальные видят «Редактирует Петрова, открыть только для чтения».
- Автосохранение черновика каждые несколько секунд.
- При конфликте версий — показ различий, а не молчаливая перезапись.
- Живое обновление списков (кто-то внёс результат — у всех обновилось без перезагрузки).
- Все изменения подписаны автором и временем.

## 7. Объём и нагрузка

- 5 врачей + лаборатория, около 30 процедур в неделю ≈ 1500 в год.
- За 5 лет — порядка 7–8 тысяч процедур. Для базы это немного; узкое место не производительность, а удобство ввода.
- Первичный импорт: более 100 карт (файл будет позже).

## 8. Данные и безопасность

- HTTPS обязательно; на арендованном сервере — шифрование диска.
- Роль-ориентированный доступ, журнал всех изменений и входов.
- Резервное копирование ежедневно, с проверкой восстановления.
- Ретенция: ничего не удаляется, аннулирование с причиной.
- Развёртывание сначала на арендованном сервере, позже — перенос в контур учреждения. Поэтому всё упаковано в контейнеры и переносится без переписывания: меняется только строка подключения к базе и домен.

## 9. Техническая основа

- Единый стек TypeScript — один язык для веба, API и телеграм-бота, один репозиторий, одна база.
- Бэкенд: Node 22 + Fastify + Prisma.
- База: SQLite при разработке, PostgreSQL на сервере (переключается провайдером Prisma, схема одна).
- Фронтенд: React + TypeScript + Vite. Плотный табличный интерфейс, быстрый ввод с клавиатуры.
- Бот: grammY, тот же API и та же база.
- Аутентификация: сессионные cookie, пароли через bcrypt, роли проверяются на уровне API.
- Экспорт Excel: exceljs.
- Развёртывание: Docker Compose, один сервер.

Справочники (показания, методы, категории результатов, осложнения, исходы) — строки в базе, а не жёстко зашитые перечисления: заведующий добавляет своё значение без программиста.

## 10. Порядок реализации

1. **Этап 1 (ядро).** Вход и роли, пациентки, беременности и плоды, скрининг, мастер процедуры, журнал процедур, справочники, экспорт Excel.
2. **Этап 2 (лаборатория).** Очередь образцов, ввод результатов, статусы, дедлайны.
3. **Этап 3 (замыкание цикла).** Исходы, задачи-напоминания, уведомления в интерфейсе, дашборд, аналитика.
4. **Этап 4.** Импорт накопленных карт из Excel.
5. **Этап 5 (телеграм).** Привязка, уведомления, поиск по коду, фото, 2FA.

## 11. Открытые вопросы

1. Есть ли МИС, из которой можно тянуть пациенток, или всё вводится вручную (пока исходим из ручного ввода).
2. Домен и сервер для размещения — понадобятся к моменту первого развёртывания.
3. Формат накопленного Excel-файла для импорта — нужен образец.
