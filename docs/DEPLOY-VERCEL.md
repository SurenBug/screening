# Развёртывание на Vercel

Репозиторий подготовлен так, чтобы Vercel собирал и интерфейс, и API одним проектом:
собранный фронтенд отдаётся как статика, а всё, что начинается с `/api`, уходит
в бессерверную функцию `api/index.ts` — это тот же самый сервер Fastify.

---

## Сначала — о чём нужно знать

Vercel — публичное облако за пределами вашего учреждения. Ниже честный список
того, что там работает иначе, чем на своём сервере.

| Что | На своём сервере | На Vercel |
|---|---|---|
| База данных | PostgreSQL в вашем контуре | внешняя (Neon, Vercel Postgres) — данные лежат у стороннего провайдера |
| Загруженные снимки | хранятся на диске | **теряются**: у функции только временная папка, живущая один запрос |
| Распознавание фото | 0,5–3 с, локально | работает, но первый запрос после простоя медленный: поднимается контейнер и грузится модель |
| Персональные данные | не покидают учреждение | покидают |

Из этого следует простая вещь: **Vercel хорош, чтобы показать сервис, потренироваться
и согласовать доработки. Для реальных данных пациенток он не подходит** — это прямо
противоречит решению распознавать документы только внутри своего контура.
Для рабочей эксплуатации остаётся [docs/DEPLOY.md](DEPLOY.md) — свой сервер.

Если сервис на Vercel всё же будет открыт людям, заводите там только вымышленные
данные.

---

## Шаг 1. Подключить репозиторий

1. Зайдите на [vercel.com](https://vercel.com) под своей учётной записью GitHub.
2. **Add New → Project**, выберите репозиторий `SurenBug/screening`.
3. Ничего не меняйте в настройках сборки: они уже заданы в `vercel.json`
   (команда сборки, папка `web/dist`, функция `api/index.ts`).
4. Пока не нажимайте Deploy — сначала база.

## Шаг 2. Завести базу данных

В том же проекте: вкладка **Storage → Create Database → Postgres** (или подключите
внешнюю базу, например [Neon](https://neon.tech) — бесплатного тарифа хватает с запасом).

Vercel сам добавит в проект переменную `DATABASE_URL`. Если подключаете свою базу,
задайте её вручную: **Settings → Environment Variables**.

## Шаг 3. Переменные окружения

**Settings → Environment Variables**, для всех сред (Production, Preview, Development):

| Имя | Значение | Зачем |
|---|---|---|
| `DATABASE_URL` | строка подключения к PostgreSQL | база |
| `NODE_ENV` | `production` | включает защищённые cookie |
| `SESSION_TTL_HOURS` | `12` | через сколько часов истекает вход |
| `UPLOAD_DIR` | `/tmp/uploads` | единственная папка, доступная функции для записи |

## Шаг 4. Создать таблицы и наполнить справочники

Это делается один раз, со своего компьютера — в бессерверной функции миграции не запускаются.

```bash
git clone https://github.com/SurenBug/screening.git && cd screening
npm install
npm run pg:schema
DATABASE_URL="строка-подключения-из-Vercel" npx prisma db push --schema server/prisma/schema.postgres.prisma
DATABASE_URL="строка-подключения-из-Vercel" npm run seed -w server
```

Последняя команда заведёт справочники и три учётные записи (`admin` / `admin123`,
`doctor` / `doctor123`, `lab` / `lab123`). **Сразу после первого входа система
потребует сменить пароль — смените все три.**

Чтобы посмотреть сервис не на пустой базе, добавьте демонстрационные данные:

```bash
DATABASE_URL="строка-подключения-из-Vercel" npm run demo -w server
```

## Шаг 5. Развернуть

Нажмите **Deploy**. Через пару минут сервис откроется по адресу вида
`https://screening-xxxx.vercel.app`.

Проверить, что API поднялся: откройте `https://ваш-адрес/api/health` — должен
ответить `{"ok":true,...}`.

## Если что-то не работает

**Белый экран, в консоли браузера ошибки 404 на `/api/...`**
Функция не собралась. Смотрите вкладку Deployments → последний деплой → Building.
Чаще всего дело в том, что не задан `DATABASE_URL`.

**`PrismaClientInitializationError`**
Строка подключения неверна или база не отвечает. Проверьте, что в `DATABASE_URL`
есть `?sslmode=require` — большинство облачных баз требуют шифрование.

**Не заходит: «Неверный логин или пароль»**
Не выполнен шаг 4 — в базе нет пользователей. Запустите `npm run seed -w server`
с production-строкой подключения.

**Распознавание фото отваливается по времени**
Первый запрос после долгого простоя поднимает контейнер и загружает языковую
модель — это может занять до минуты. Повторите. Если повторяется постоянно,
значит выбранный тариф ограничивает время выполнения функции: на бесплатном
тарифе лимит жёстче, чем указанные в `vercel.json` 60 секунд.

**Загруженные снимки пропали**
Так и будет: у бессерверной функции нет постоянного диска. Чтобы снимки
сохранялись, нужен либо свой сервер, либо объектное хранилище (Vercel Blob,
S3) — это отдельная доработка, скажите, если она нужна.

---

## Что дальше, если сервис пойдёт в работу

Переезд с Vercel на свой сервер — это смена строки подключения и домена, код
переписывать не нужно: и там, и там одно и то же приложение. Порядок действий —
в [docs/DEPLOY.md](DEPLOY.md).
